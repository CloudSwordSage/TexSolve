# TexSolve 需求规范

## 1. 目的与范围

TexSolve 是面向 Windows x64 的 LaTeX 数学表达式计算引擎。首版同时交付动态库、静态库和命令行程序，调用方通过稳定 C ABI 提交 UTF-8 LaTeX，获得可遍历的结构化结果。系统优先返回解析 LaTeX；只有解析解不可得时才返回数值近似。

本规范中的“必须”表示首版验收条件。语法细节见 [latex-syntax.md](latex-syntax.md)，接口见 [c-api.md](c-api.md)，架构见 [design.md](design.md)。

## 2. 术语

- **解析结果**：由精确常量、符号和运算组成、可重新渲染为 LaTeX 的结果。
- **数值近似**：以指定十进制有效位数计算的实数或复数结果。
- **context**：保存变量、用户函数、默认精度、资源限制和后端偏好的会话对象。
- **operation**：求值、化简、微积分、求解、优化或 ODE 等显式动作。
- **自动后端**：根据操作能力选择库；用户强制指定后端后不得静默切换。
- **协作式截止时间**：在可中断阶段检查，并传递给支持时限的后端；不承诺强杀不可中断调用。

## 3. 功能需求

### REQ-001 输入与语法

**用户故事：** 作为调用方，我希望提交常见计算型 LaTeX，从而无需使用某个后端的私有语法。

**验收标准：**

1. 系统必须接收带显式字节长度的 UTF-8 输入，不依赖 NUL 结尾。
2. 系统必须实现 [latex-syntax.md](latex-syntax.md) 的白名单语法、优先级和隐式乘法规则。
3. 非法 UTF-8、未知命令、歧义输入和尾随内容必须产生包含字节区间的诊断。
4. 系统必须拒绝 `\newcommand`、文件输入、递归宏和未列出的环境。

### REQ-002 数值与符号基础

**用户故事：** 作为用户，我希望进行科学计算和符号化简，并保留精确结果。

**验收标准：**

1. 系统必须支持整数、有理数、实数、复数、常量、变量、四则运算、幂、根式、绝对值、阶乘和白名单初等函数。
2. 可以精确表示的整数、有理数和代数表达式不得无故转成浮点数。
3. 系统必须支持变量代入、表达式化简、展开和因式分解。
4. 数值近似默认 15 位，可在 1 至 10000 位间配置；高精度由 GMP/MPFR 承担。

### REQ-003 会话定义

**用户故事：** 作为 REPL 用户，我希望连续定义变量和函数并复用它们。

**验收标准：**

1. context 必须保存变量及单参数或多参数用户函数。
2. 定义必须先完整解析和验证，失败时不得部分修改 context。
3. context 必须支持列出定义和原子清空全部定义。
4. 不同 context 可并发执行；同一 context 的并发访问由调用方串行化。

### REQ-004 微积分

**用户故事：** 作为用户，我希望用常见数学记法计算导数、积分、极限和有限求和/乘积。

**验收标准：**

1. 系统必须支持一元导数、多元偏导和高阶导数。
2. 系统必须支持常见不定积分、定积分和多重积分；符号失败时，只有边界完备的定积分可退化为数值积分。
3. 系统必须支持单侧/双侧极限以及上下界均有限且整数化的求和与乘积。
4. 不支持的无穷级数、向量微积分或无解析不定积分必须返回 `UNSUPPORTED` 或 `NO_ANALYTIC_SOLUTION`，不得伪造近似解析式。

### REQ-005 线性代数

**用户故事：** 作为用户，我希望直接计算 LaTeX 矩阵及其常见性质。

**验收标准：**

1. 系统必须支持矩阵字面量、加减乘、标量乘、转置、行列式、逆和秩。
2. 系统必须支持线性方程组、特征值和特征向量。
3. 符号输入可处理时必须保留解析结果；数值路径必须报告使用的后端和精度。
4. 非矩形矩阵、维数不匹配和奇异逆必须返回带源位置的语义诊断。

### REQ-006 方程与方程组

**用户故事：** 作为用户，我希望优先获得方程的解析根，并可受控地使用数值求根。

**验收标准：**

1. 多项式必须返回后端可得的全部实根和复根，并标示重数。
2. 一般方程和方程组必须先尝试解析求解。
3. 数值求解必须要求每个未知量提供初值或有限区间；缺失时返回 `INVALID_ARGUMENT`。
4. 超越方程的数值结果必须标记为局部/区间搜索结果，不得声称穷尽全部根。

### REQ-007 非线性优化

**用户故事：** 作为用户，我希望求解有初值和约束的最小化或最大化问题。

**验收标准：**

1. 系统必须支持一般目标、非线性最小二乘、初值、变量边界、等式约束和不等式约束。
2. 自动模式下，最小二乘优先 Ceres，其余问题优先 NLopt。
3. 用户强制选择不支持问题能力的后端时必须返回 `BACKEND_UNSUPPORTED`，不得切换后端。
4. 结果必须包含终点、目标值、收敛状态、迭代次数和后端名称；未收敛不得伪装为成功。

### REQ-008 ODE 初值问题

**用户故事：** 作为用户，我希望求解常微分方程及方程组的初值问题。

**验收标准：**

1. 系统必须接受一阶和高阶 ODE；高阶方程必须规范化为一阶系统。
2. 输入必须提供积分区间、初始时刻和完整初值。
3. SUNDIALS 路径必须返回采样时间与状态组成的结构化轨迹，并报告步数和终止原因。
4. DAE、边值问题和缺少初值的问题必须明确拒绝。

### REQ-009 后端选择

**用户故事：** 作为高级用户，我希望按计算类别选择后端并复现实验结果。

**验收标准：**

1. 符号后端可选 SymEngine/GiNaC，线代可选 Eigen/Armadillo，积分可选 GSL/Boost.Math，优化可选 Ceres/NLopt。
2. GMP/MPFR 是精确/高精度固定实现，SUNDIALS 是 ODE 固定实现。
3. `AUTO` 必须依据能力表确定后端并把实际选择写入结果。
4. 显式后端不可用或能力不匹配时必须报错，不得静默回退。

### REQ-010 结构化结果与诊断

**用户故事：** 作为库调用方，我希望稳定地遍历计算结果和错误，而不是解析显示文本。

**验收标准：**

1. 结果必须通过不透明树提供 kind、可选名称、子节点、精确 LaTeX、可选近似值、后端和诊断。
2. 结果不得暴露内部 AST 或任何第三方库类型。
3. 所有失败必须映射为稳定状态码；异常不得跨越 C ABI。
4. 解析与语义诊断必须包含严重性、机器可读代码、UTF-8 消息和输入字节区间。

### REQ-011 CLI 与 REPL

**用户故事：** 作为终端用户，我希望交互计算或把 TexSolve 用在脚本中。

**验收标准：**

1. `texsolve` 必须支持位置参数、stdin、UTF-8 文件；无输入源时进入 REPL。
2. CLI 必须支持自动数学记法和显式 operation 子命令。
3. CLI 选项必须同时提供 `--word` 长形式和对应的单字母短形式；帮助、版本、REPL、文件、调试、精度与后端分别为 `--help/-h`、`--version/-v`、`--repl/-r`、`--file/-f`、`--debug/-d`、`--precision/-p`、`--backend/-b`。后端选项接受类别和名称，并在帮助中枚举全部合法组合。
4. 标准输出只承载正常结果；诊断和 `--debug`/`-d` AST 写入 stderr。
5. REPL 必须支持 `:help`/`:h`、`:help backend`/`:h backend`、列出/清空定义、设置精度、设置后端和退出。交互输入中，`Ctrl+C` 必须取消当前行并换行，非空行末显示 `^C` 且不得求解；空手工输入可用上下箭头按新到旧/旧到新浏览历史，已调出的历史行仍可继续浏览。

### REQ-012 稳定 C ABI 与产物

**用户故事：** 作为集成方，我希望用同一公开头链接动态库或静态库。

**验收标准：**

1. 项目版本为 `0.1.0`，ABI 版本为 `1`；顶层跨版本结构必须带 `struct_size` 和 `abi_version`，嵌套结构由所属顶层 ABI 版本和显式 stride 管理。
2. 动态库、静态库和 CLI 必须使用同一公开 C 头；CLI 默认动态链接 DLL。
3. 所有分配对象必须由创建它的库函数释放，调用方不得跨 CRT 释放。
4. 安装结果必须提供 CMake package，使下游可分别链接共享或静态目标。

### REQ-013 资源、可靠性与性能

**用户故事：** 作为宿主程序，我希望畸形或昂贵输入不会无界消耗资源。

**验收标准：**

1. 默认上限为 64 KiB 输入、128 层嵌套、50000 AST 节点、10000 次迭代、5 秒协作式截止和 10000 位精度。
2. 合法范围内的上限可按请求覆盖；零值表示使用 context 默认值，不表示无限。
3. 实际资源消耗允许等于配置上限；首次尝试超过上限时必须返回 `RESOURCE_LIMIT`。截止检查时已用墙钟时间大于或等于截止值必须返回 `DEADLINE_EXCEEDED`；两类失败均须保留诊断且不得提交部分会话定义。
4. Release 模式下，≤1 KiB 常见标量表达式预热后执行 100 次，解析加求值 p95 必须不超过 50 ms。

### REQ-014 平台与构建

**用户故事：** 作为维护者，我希望在现有离线依赖上可重复构建、测试和安装。

**验收标准：**

1. 首版只保证 Windows x64、MSYS2 UCRT64 GCC、C++20 和 Ninja。
2. CMake 不得下载依赖，必须只使用仓库 `third_party/` 中的已编译产物。
3. 构建必须生成 DLL、静态库、动态链接 CLI、测试和安装包配置。
4. 所有 GCC 构建与测试命令必须通过 `bash -c '...'` 执行。

## 4. 明确不在首版范围

- 完整 TeX 引擎、自定义宏、排版渲染和文档级 LaTeX。
- DAE、ODE 边值问题、无穷级数、梯度/散度/旋度及高级矩阵分解公开接口。
- MSVC ABI、32 位 Windows、Linux/macOS 构建验证和运行时第三方插件加载。
- 对任意超越方程“找全所有根”的承诺。
